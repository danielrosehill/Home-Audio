# Setup: the private installation record

The plugin is public and generic. Everything about *this* household's audio lives in the
overlay folder, which can be its own private git repository. That is where server
addresses, endpoints, sinks, rooms and history are kept.

## Steps

1. Resolve the folder: `bash ${CLAUDE_PLUGIN_ROOT}/scripts/overlay-paths.sh` (prints `data_dir`
   and the rule that picked it). If `profile.env` already exists, show it and only fill gaps.
2. Detect before asking. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audioctl.py scan --subnet <the LAN /24 of this machine>`
   and `audioctl.py mdns`. Read the hits with `${CLAUDE_PLUGIN_ROOT}/reference/ports.md` to propose:
   primary backend, Music Assistant URL, LMS host, snapserver host, Home Assistant URL.
3. Ask only for what detection could not settle: which backend is primary, the names of
   the environment variables that will hold the Music Assistant and Home Assistant tokens,
   and how secrets reach a process (a wrapper command, an env file). Never ask for or store
   the token values themselves.
4. Write `profile.env` from `${CLAUDE_PLUGIN_ROOT}/templates/profile.env` (every key documented there).
   Put the secrets route as a comment line; skills follow comments.
5. Write `installation.json` from `${CLAUDE_PLUGIN_ROOT}/templates/installation.json` with what step 2 found, then
   run the `inventory` skill to fill endpoints.
6. Offer to make the folder a private git repo:
   `git init`, then `gh repo create <name> --private --source . --push`. Suggest a name like
   `Home-Audio-Record`. Default private; it holds IPs, hostnames and room names.

## Overlay layout

```
<data_dir>/
  profile.env            settings (keys in templates/profile.env)
  installation.json      canonical inventory: servers, endpoints, HA, history
  installation.md        human rendering of installation.json (regenerated by inventory)
  endpoints/<host>.md    per-endpoint notes: hardware, quirks, what was changed and when
  dsp-presets/<n>.json   user DSP presets; same name as a built-in wins
  changelog.md           dated log of changes the skills made
  <skill-name>.md        private notes for one skill; they override its defaults
```

## Data storage

Writes only inside the resolved overlay folder, and says the path when it does.
Caches (scan results) may go to `${CLAUDE_PLUGIN_DATA}`. Nothing is written to the plugin.
